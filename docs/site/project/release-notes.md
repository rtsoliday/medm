# Release notes

## QtEDM 1.1.0

Changes since QtEDM 1.0.0. `qtedm -version` and **Help > About QtEDM** report the release.

### Security

- **Shell Command macro check.** QtEDM records where each display macro value was substituted into a Shell Command, checks each value in its own quoting context, and refuses the command with a message explaining why when a value breaks the rules. Macros the command does not use never block it. A quoted value may contain characters such as braces, parentheses, `#`, or `*`. An unquoted value is limited to letters, digits, spaces, and `_ . / : @ + = , - % ~`, plus braces when it contains no comma or `..`. PV names such as `SR:C01-BI{BPM:1}Pos:X-I` work quoted or unquoted. A value containing an option word such as `-e` is refused. Each value is checked on its own, so values joined to each other or to neighboring text can still form an option word or a brace expansion; do not join macros whose values you do not control in option positions. A command edited in the display editor, or rebuilt by undo, redo, or paste, uses a stricter check until the display is opened again. The [Shell Command reference](../reference/widgets#WidgetShellCommand) gives the exact rules and limits. Execute menu commands from `MEDM_EXEC_LIST` are not checked.
- **Dynamic Shell Command values.** On Unix, the `&A`, `&T`, and `&P` values QtEDM inserts into a Shell Command are quoted so the shell does not interpret them, and values containing control characters such as line breaks are refused. A command that places `&A`, `&T`, or `&P` after a backslash, or inside or after command substitution, backquotes, or a here-document, where quoting cannot protect them, is refused with a message; QtEDM 1.0.0 and MEDM ran it.
- **Read-only mode.** `--read-only` now blocks Shell Commands and `MEDM_EXEC_LIST` Execute menu commands, as documented.
- **Literal macro values.** As in MEDM, a macro value is inserted literally into the display file. Backslash escapes in a value are no longer decoded, so `C:\temp` no longer becomes a tab, and a quote, brace, or space in a value can no longer end a string or add display elements.
- **Input limits.** Remote display requests are limited to 64 KiB; a `qtedm` that cannot send its request to a running QtEDM reports it and exits with status 1. Sessions are limited to 4 MiB and 100 windows. The animated GIF frame cache is limited to 64 MiB per image and 256 MiB in total. A related display's macro arguments may expand to at most 16 Mi characters, the limit of a display file; beyond it the display does not open.
- **Hardened Linux build.** The executable is built as a position-independent executable with full RELRO, immediate binding, a stack protector, and a non-executable stack. QtEDM no longer raises the core-dump size limit at startup.

### Behavior changes

- **Writes are shown when the IOC reports them.** After a Channel Access write, monitors of the PV no longer show the requested value before the IOC confirms it. If the IOC clamps, rejects, or overrides the write, the display keeps showing the IOC's value and alarm state. The control making the write shows the value you set until the IOC reports a value, then shows the IOC's value, as in MEDM, even when that value has not changed. If the IOC reports no value, the control keeps showing the value you set.
- **Macros as in MEDM.** Where a macro name is given twice, as by a related display that passes `LOC` twice, the first value is used; QtEDM 1.0.0 used the last, so such a child display can now connect to different channels. Whitespace inside macro names and values from `-macro`, a related display, or a composite file is removed: `TITLE=Beam line` gives `Beamline`, and the missing comma in `xx=05 yy=BM` gives `xx` the value `05yy=BM`. A blank `-macro " "` defines no macros instead of being read as a display file name.
- **Composite files inherit display macros.** A composite file without its own macros now resolves `$(P)` and similar references from the display's macros, as MEDM does. Macros given with the composite file name are added to the display's macros and take precedence. MEDM instead uses only the composite's own macros when it has any.
- **Limits as in MEDM.** An upper limit that comes from its default, with no value given, is MEDM's 1 instead of 100 for bars, sliders, scale monitors, strip chart pens, wheel switches, and thermometers. A slider, wheel switch, scale monitor, or strip chart pen without a `limits` block, as in displays older than MEDM 2.2 or written by other tools, takes its limits from the channel, as MEDM does, instead of a fixed range that also bounded the values a slider or wheel switch writes. So does a slider, wheel switch, or scale monitor created in the editor; QtEDM 1.0.0 gave it default limits of 0 to 100. Equal channel limits other than 0 to 0, such as 5 to 5, are kept as MEDM keeps them; QtEDM 1.0.0 widened them to 5 to 6, so a slider or wheel switch could write 6.
- **Negative hexadecimal values** show as their low 32 bits, as in MEDM, so -2 shows as `0xfffffffe` instead of `-0x2`. Entering such text in a hexadecimal text entry, text area, or setpoint control, or with its `0x` prefix in a text entry or setpoint control of another format, writes the negative value to a short or long Channel Access channel.
- **Choice buttons clip long labels** to the button instead of drawing past its edge.
- **Slider steps as in MEDM.** An arrow key or a click in the trough adds or subtracts exactly the increment. QtEDM 1.0.0 snapped the result to multiples of the increment counted from the lower limit, so a step up from 3.5 with an increment of 1 wrote 5 instead of 4.5.
- **Menus and wheel switches ignore the mouse wheel**, as in MEDM. Scrolling over a menu changed its item, and scrolling over a wheel switch stepped its value, each writing the channel.
- **Choice buttons need an enum channel.** As in MEDM, a choice button whose channel is not an enum draws no buttons, writes nothing, and reports that the channel is not an ENUM type. QtEDM 1.0.0 drew "0" and "1" buttons for such a channel.
- **Resource Palette** sizes itself to the screen, keeps the size you choose, and aligns its columns.
- **Saved numbers** use the shortest exact form where fixed notation would lose precision.
- **Symbol state colors** can be edited with an alpha channel in the editor. Saving stores the nearest palette color.
- **Plugin string-list properties** are entered in the Resource Palette as a JSON array, such as `["first", "second"]`, instead of semicolon-separated text. Invalid input restores the previous value.
- **NTNDArray image limits.** Maximum Input and Maximum Image are entered in bytes instead of MiB and are no longer capped at 4096 MiB. Maximum Dimension is no longer capped at 65536.
- **Build variables.** `CC`, `CXX`, `CPPFLAGS`, `CXXFLAGS`, and `LDLIBS` set in the environment no longer change the build. Pass them on the `make` command line instead. `LDFLAGS` set in the environment is still added to the link on Linux and Windows.
- **SDDS** is no longer required to build QtEDM. A build check confirms SDDS6 export where SDDS is available.
- **Disconnected objects as in MEDM.** An object whose color and visibility are static draws normally while its channel is disconnected. A child hidden by its own visibility stays hidden in a shown composite. Disconnected widgets are stacked with the graphics in display order, so graphics drawn after them cover their white boxes.
- **Cartesian plots as in MEDM's SciPlot.** Margins, fonts sized from the plot, tick increments and labels, markers, and time axes that span the data follow SciPlot, as does the title offset of displays older than file version 030115. The dotted grid is drawn only with `drawMajor=1`, which QtEDM saves for a plot with a grid; plots saved by QtEDM 1.0.0 with the default grid have no such key and now show no grid. A plot is white while any trace, trigger, erase, or count channel is disconnected, and a count that starts with a digit is read as a number. A string channel's trace plots at 0, and an axis whose channels have no usable display limits autoscales, for `pva://` channels as for Channel Access ones.
- **Widgets drawn as MEDM's Xc and Motif widgets.** Scale monitors, bars (with their 20x20 minimum while connected), sliders, strip charts, choice buttons, menus, text entries, related display and shell command buttons, and bevel shadow colors follow MEDM's layout and drawing. A disconnected text entry is drawn without its bevel.
- **Graphics drawn as by MEDM's X server.** Ovals cover the pixels of `XFillArc` and `XDrawArc`, dashed and wide lines use 4-pixel dashes and butt caps, outline rectangles thinner than their line width are drawn, display images fill their object without smoothing, and a composite's static graphics stack in display order and are clipped to its object when it has a channel.
- **Qt warnings go to standard error**, as MEDM's messages do, even when standard error is not a terminal, unless `QT_FORCE_STDERR_LOGGING` is already set. Shell commands inherit that setting.
- **Large displays fill faster.** When Channel Access delivers more events than QtEDM's inbox holds, each channel keeps its newest value instead of losing the oldest events, which could be a channel's only value, and only elements whose stacking order changed are restacked.

### Fixes

- Legacy (pre-2.2) ADL files whose quoted values contain braces, such as `chan="SR:C01{BPM}"`, load correctly. As in MEDM, their dynamic attributes' `mod` and `param` settings, also when written on one line such as `param { chan="X" }`, apply to the next object, and a basic attribute stays in effect for later objects.
- ADL files with an extra `}` between objects open as they do in MEDM instead of failing with "Expected section or key".
- A backslash in an ADL string, other than in the escapes QtEDM writes, is kept as MEDM shows it, so `Faults\Trips` no longer reads `FaultsTrips`.
- Object geometry and polyline or polygon points written with a fraction, such as `y=57.2`, keep their integer part, as in MEDM, instead of falling back to 0 or dropping the point.
- A display saved with a negative position opens at the edge of the screen, as MEDM moves it, instead of partly off the screen.
- A `-dg` geometry with a position, such as `qtedm -x -dg +100+200 display.adl`, no longer crashes QtEDM.
- The tick labels of a zoomed or panned cartesian plot sit where their values are plotted. They were spread over the zoom window rounded out to nice values, so a label could be up to one tick step away from the data at its value.
- A cartesian plot autoscaled over a value near the largest double, such as a 1.8e308 sentinel, keeps its ticks and draws the other points where they belong instead of all at the bottom.
- A cartesian plot's log axis pans and zooms in decades. A one-pixel drag could move its minimum below 0, which hid every point and labeled the axis linearly. A click that moves less than the drag distance, or a sideways scroll or tilt of the mouse wheel, no longer freezes the axes in a zoomed state, and zooming stops before an axis loses its range.
- A cartesian plot of a `pva://` channel whose server sends no display limits or precision, such as an NTScalar without display metadata, autoscales its axis once the first value arrives. It stayed white.
- A rejected setpoint edit no longer stays displayed as if it had been applied.
- A Spin Box step from a value outside its limits is refused, as Enter refuses that value. The + and - buttons clamped the step to the limits, so + on a value above the high limit wrote the high limit, moving the setpoint down. Before the channel sends a value, the buttons write nothing instead of stepping from 0.
- The + and - buttons of a hexadecimal or octal Spin Box write the next whole number. They sent the next value as decimal text, which the control read in its own base, so + on a hexadecimal 9 wrote 16 and octal steps were refused.
- A wheel switch steps as in MEDM. A value outside its limits steps toward them by the step you choose; it used to write the nearest limit, so one Down click on a value of 50 with limits 0 to 1 wrote 1. A step that would pass a limit, or the largest value the format shows, does nothing; holding a button or pressing Page Up used to write the limit. A step is rounded to the decimals of the format, so a 0.01 step from 1.23456 writes 1.24 for a two-decimal format instead of 1.24456. A digit shows its buttons, and its arrow keys step, only where the step stays within the limits or comes back within them, so a switch at 50 with limits 0 to 1 no longer offers a tens step down to 40.
- A slider writes a step however small it is against its limits. A step of at most a millionth of their span, such as 0.001 for limits 0 to 1000, was dropped, so arrow keys and clicks in the trough did nothing.
- A slider or wheel switch whose channel has not sent a value, or sends only NaN, writes nothing for an arrow key, a click in the slider's trough, or Page Up or Page Down. It stepped from a made-up value, so a slider with channel limits 100 to 200 could write 1.6.
- A wheel switch whose button or arrow key is held when its channel disconnects or loses write access stops stepping. It ignored the release while it could not write, then stepped and wrote by itself every 90 ms once the channel came back with write access.
- An arrow key or trough click on a slider whose value is outside its limits moves the value by the increment and stops only at the limit it moves toward, as in MEDM. It used to write the opposite limit, so one step down from 50 with limits 0 to 1 wrote 1.
- A slider whose channel limit lies beyond the range of a float, and so becomes infinite as in MEDM, no longer writes the 0-to-1 position of its thumb when dragged. Its thumb does not drag; arrow keys and clicks in the trough step by the increment.
- Dragging a slider's thumb keeps the point where it was grabbed under the pointer, as in MEDM. The first motion jumped the thumb's center to the pointer, so grabbing a 200-pixel slider near the edge of its thumb and moving one pixel could write a value several percent of its range away.
- Menus, related display buttons, and wave tables fit their labels and empty-state text to the widget.
- A strip chart pen whose channel limits are less than 1e-9 apart, such as a vacuum gauge in Torr, is drawn over those limits, as in MEDM, instead of over a range of 1 that put the trace along the bottom.
- Related display and shell command buttons show their icon and label as MEDM does: together, centered on a button with one item and at the left of a menu button, with the label's leading spaces kept. On a small button the label no longer covers the icon. A row or column of related display buttons with at most one label is one button, as in MEDM, and opens the first display with a name.
- Text 16 to 19 or 21 to 25 pixels high is no longer wider than in MEDM. The fonts for those heights had no space character, so spaces were drawn from a wider font and long labels could be cut off.
- Composites no longer cut off their contents in execute mode. A button, outline, or label that extends past its composite's stored size is drawn in full, as in MEDM, and a composite file's contents start at the composite's position instead of a few pixels away.
- An archive strip chart whose live channel disconnects, or whose history arrives while that channel is gone, keeps its history and keeps scrolling with a gap for the time the channel is gone. It repeated the last value, which scrolled on as if the channel were still reporting, or with no other live channel stopped with that value at the right edge. Once the channel reports again, the line joins the samples on either side of the gap, as it joins archived samples.
- `make clean` works on Windows, and QtEDM compiles without warnings.

### Known issues

- Saving a display written by MEDM rewrites strings that contain backslashes. QtEDM decodes the escapes it writes, such as `\t`, when it reads a file, and saves each backslash as `\\`, which MEDM shows as two backslashes. Keep an original copy of MEDM displays whose labels or shell commands contain backslashes.
- Opening a display with unreachable `pva://` PVs pauses for about one second per PV.
- As in MEDM, a negative value of a float, double, or char Channel Access channel shown in hexadecimal, such as `0xfffffffc` for -4, reads back as a large positive number, so entering the text shown writes 4294967292. Enter negative values of such channels in decimal.
- A `pva://` channel reports every numeric type as a double, so hexadecimal or octal text from `0x80000000` to `0xffffffff` entered for a signed integer `pva://` PV is written as a large positive number, which does not fit the PV. A negative value of such a PV is shown in that range. Enter negative values of `pva://` integers in decimal.
